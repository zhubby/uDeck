# CM4 桌面性能修复与实机验证

本轮修复 Home、Apps 与页面切换卡顿。
音效和短过渡保持开启。
测试机为 uConsole CM4，4 个逻辑 CPU。
系统为 Debian 13.5 arm64、Qt 6.8.2、labwc 和 V3D。
基线为 `d0ab039beb3dfb16faa326f0e73293ea7a125dda` 的 1.0.0。
最终安装包为工作区未提交源码的 1.0.1 测试包。

## 根因与改动边界

### 定时输入扫描阻塞界面线程

`PointerGuard._scan` 每秒打开并关闭非指针接口。
CM4 上每次 evdev 关闭耗时约 16–44 ms。
8 个被排除的接口累计阻塞约 200 ms。
独立观察进程在停顿中请求 GDB 栈。
多次捕获均指向以下调用链：

```text
evdev.InputDevice.close
  → PointerGuard._scan
  → 桌面主事件循环
```

此前 strace 未跟踪 `close`，漏掉该系统调用。
延迟采集的 Shiboken 事件过滤栈也不能定位根因。
最终依据停顿中的栈和独立扫描对照修复。

`pointer.py` 先读 sysfs 输入能力位图。
非指针接口不再打开 evdev。
候选指针仍由 evdev 校验独占条件。
每轮重读位图，支持热插拔和 event 路径复用。
位图不可读或格式错误时沿用 evdev 校验。

相同设备各扫描 6 次：

| 扫描方式 | 中位数 | 最大值 | evdev 打开次数 |
| --- | ---: | ---: | ---: |
| 原扫描 | 283.348 ms | 332.007 ms | 48 |
| sysfs 预筛选 | 3.678 ms | 4.124 ms | 0 |

### 短音效放大音频服务负载

`QSoundEffect` 反复启动短音效流。
同机、同一音效、每秒 5 次，共 50 次的顺序对照：

| 音频传输 | 音频服务 CPU 合计 | 事件循环最大间隔 |
| --- | ---: | ---: |
| QSoundEffect | 单核 94.126% | 124.736 ms |
| 持续 PCM 流 | 单核 2.498% | 8.636 ms |

音频服务包含 PipeWire、兼容服务和 WirePlumber。
此处 100% 代表占满一个核心。
PCM 对照接收 50/50 次请求，无缓冲欠载。

`interface_audio.py` 复用一条 48 kHz 单声道音频流。
音频对象和供数计时器全部归播放线程。
`sounds.py` 只在界面线程提交语义反馈。
邮箱合并待播事件，取消旧代事件，丢弃过期音效。
导航音效限制为 90 ms，后台窗口立即取消播放。
设备变更重新建立输出；离屏静音不创建播放线程。

### 重复视图发布放大导航成本

`controller.py` 分离视图发布和选择索引发布。
Home、Apps 导航不再序列化完整快照。
`Main.qml` 直接绑定索引和导航区域。
页面模型与滚动位置继续复用。
隐藏的系统清单不进入视图载荷。
相同实机数据的载荷从 20508 降为 6344 bytes。
完整诊断接口仍保留系统清单。

`input.py` 对重复前台状态不再释放输入设备。
`compatibility.py` 在桌面内切页时保持输入归属。
`backend.py` 不重复发布相同音频控制状态。
`runtime_console/service.py` 丢弃过期回复。
相同应用状态不触发 Console 重建。

## 正式桌面对照

使用真实系统后端、6 个空闲套件应用和正常音效。
导航通过内置键盘接口注入成对 EV_KEY。
数值为 D-Bus 请求返回耗时，包含界面队列等待。
它不等于物理按键到屏幕像素的延迟。

| 操作 | 1.0.0 中位数 / P95 / 最大值 | 最终安装包中位数 / P95 / 最大值 |
| --- | ---: | ---: |
| Home 导航诊断 | 73.415 / 256.560 / 320.036 ms | 2.179 / 7.075 / 60.733 ms |
| Home、Apps、Console 切页 | 130.226 / 354.277 / 384.099 ms | 50.220 / 81.283 / 137.575 ms |
| 关闭菜单后的诊断 | 67.809 / 213.332 / 213.332 ms | 1.593 / 3.091 / 3.091 ms |

菜单阶段在开关后各等待 200 ms。
该阶段测量剩余队列等待，不测量菜单打开耗时。
短轮次仍有一次 137.575 ms 的切页请求。
不能将全部测试描述为零次超过 100 ms。

正式后端下的最终资源采样：

| 状态 | 桌面 CPU，100% 为单核 | 桌面 PSS | 全机 CPU，100% 为 4 核 |
| --- | ---: | ---: | ---: |
| 亮屏静置 | 8.545% | 110.531 MiB | 12.076% |
| 连续 Home 导航 | 52.407% | 111.181 MiB | 27.239% |
| 连续切页 | 78.616% | 121.121 MiB | 34.263% |

桌面组包含其小型 pactl 订阅子进程。
PSS 按共享内存比例计费，避免 RSS 重复相加。
以上阶段没有 swap 换入换出，降频标志为 `0x0`。
循环在回复后等待，较快版本完成更多次操作。
此处 CPU 比例不能用作固定工作量的降幅对照。
音频服务降幅由前述固定 50 次音效对照支持。

## 持续输入与真实控制路径

正式桌面持续测试耗时 272.97 秒。
完成 3660 次键盘操作、120 次切页和 30 轮菜单开关。

| 阶段 | 样本数 | 中位数 / P95 / 最大值 |
| --- | ---: | ---: |
| Home 导航诊断 | 1500 | 2.155 / 13.365 / 49.825 ms |
| Apps 导航诊断 | 1500 | 2.231 / 18.776 / 50.937 ms |
| Console 导航诊断 | 600 | 5.528 / 23.978 / 56.405 ms |
| 切页 | 120 | 37.831 / 67.846 / 91.811 ms |

该轮全部阶段均无超过 100 ms 的请求。
线程数保持 17。
PSS 从 126266 增至 127714 KiB，约增加 1.4 MiB。
句柄数在 50–58 间变化，结束为 56。
这段有限观测不能证明所有工作负载下无内存泄漏。

内置肩键另完成 120 次来回切页。
按下到诊断确认包含 20 ms 的按住时间。
中位数 34.437 ms，P95 为 64.018 ms，最大 76.362 ms。
没有丢失页面切换，也没有超过 100 ms 的样本。
脚本曾在事件处理前读取状态，已改为有界等待。
计时在证据写盘前结束，排除测试日志开销。

8 张实机截图已逐张核对：
肩键切到 Apps、切回 Home，Y 打开快捷设置。
A 打开音量菜单，B 关闭菜单返回 Home。
音量菜单沿用替换快捷设置的现有行为。
再次 Y 打开快捷设置，B 关闭返回 Home。
测试没有改变音量或打开用户内容。

## 已安装 QML 的隔离渲染检查

测试导入系统安装路径，使用真实 Wayland 和 GPU。
后端与配置隔离，数据集来自同机目录规模。

两页移动均为零次完整快照，无音频欠载。

持续渲染测试完成 1200 次导航、200 次切页和 40 轮菜单。
Home、Apps 首个帧信号 P95 分别为 16.003、16.959 ms。
切页 P95 为 26.552 ms，最大 39.874 ms。
菜单首个帧信号 P95 为 78.986 ms，最大 115.917 ms。
全部阶段无超过 50 ms 的帧信号间隔。
QML 错误为空，无音频欠载，初始固定控件未销毁。
高频导航按 90 ms 规则合并音效。
软件帧信号不代表 GPU 完成，也不代表光学延迟。
