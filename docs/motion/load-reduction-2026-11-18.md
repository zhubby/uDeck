# CM4 后台负载优化与实机复验

本轮继续减少桌面和套件应用的后台空转。
测试机为 4 核 uConsole CM4。
系统为 Debian 13.5 arm64、Qt 6.8.2 与 labwc。
本轮基线为上一轮已安装的 1.0.1 测试包。
上一轮卡顿修复见 [performance-2026-11-18.md](performance-2026-11-18.md)。

## 实机定位与代码边界

亮屏 Home 静置 30 秒，保留 6 个已打开应用。
Web 共享启用且运行；SMB 共享关闭。
桌面 CPU 为单核 7.416%，PSS 为 132.570 MiB。
音效线程占单核 2.660%，QtPulse 线程占 0.765%。
关闭的 SMB 服务仍占单核 4.223%。
12 秒内，5 个后台应用调用 60 次 `NativeInputState`。
采样没有 swap 换入换出，降频标志为 `0x0`。

改动覆盖以下边界：

- `interface_audio.py` 在音效结束并安静 0.5 秒后暂停音频流和供数计时器。下一次播放复用原流。
- `apps/common/input.py` 在后台停止输入授权查询。前台授权后等待桌面推送。服务归属变更触发恢复，前台回退保留重试。
- `sharing.py` 在共享关闭且菜单隐藏时停止状态查询。相同状态不刷新桌面。打开菜单时强制读取最新状态。
- 两个共享守护进程在关闭时停止网络发现。状态请求按需读取网络。启用后继续检查网络、期限和所有者退出。

状态去重首次完整回归发现字典引用问题。
调用方复用字典会使新错误提示漏刷新。
控制器现保存独立状态快照。
原失败测试先复现失败，再通过修复。
关联翻译、共享与撤销回归共 61 项通过。

## 固定播放量对照

同机顺序运行相同音效和相同播放次数。
每轮包含 10 次稀疏播放和 50 次连续播放。
100% CPU 代表占满一个核心。

| 阶段 | 原音频进程 CPU | 已安装音频进程 CPU | 原供数回调 / 已安装回调 |
| --- | ---: | ---: | ---: |
| 初始空闲约 6 秒 | 2.807% | 0.000% | 570 / 0 |
| 每秒 1 次，共 10 次 | 2.843% | 2.532% | 984 / 600 |
| 每秒 5 次，共 50 次 | 3.200% | 3.101% | 1001 / 999 |
| 播放结束后空闲约 3 秒 | 2.666% | 0.000% | 301 / 0 |

两轮均复用一条音频流。
已安装版本恢复原流 11 次。
两轮均接收并完整写入 60 段音效，无欠载。
数据验证覆盖 PCM 写入，不包含人工扬声器听感。
连续播放 CPU 接近，空闲阶段降为零。
后台暂停的收益由空闲 CPU 和零回调共同支持。

## 服务与渲染边界

实机私有 D-Bus 测试使用真实服务归属信号。
后台、前台授权后、后台服务变更均为零重复查询。
前台丢失桌面服务后启用回退。
桌面服务恢复后重新授权并停止重试。
该探针使用输入设备替身，不抓取机身按键。

关闭的 Web 共享在 10.4 秒内零次后台网络发现。
两次状态请求分别执行一次真实系统网络读取。
两次均读到两个候选网络。
该探针运行于私有会话总线，不改变正式共享。

已安装 QML 使用真实 Wayland、GPU、fcitx 与 qt5ct。
探针使用隔离后端与配置，不替代正式桌面测试。
数据规模为 63 个应用和 486 个时区。
全屏测试中，Home、Apps 首帧信号 P95 为 20.423、17.677 ms。
切页首帧信号 P95 为 42.546 ms。
两页选择移动均为零次完整视图快照。
24 次选择分别接收 24 次音效，16 次切页接收 16 次音效。
QML 错误为空，无音频欠载。
全部阶段无超过 50 ms 的帧信号间隔。
帧信号不是 GPU 完成时间，也不是光学延迟。
