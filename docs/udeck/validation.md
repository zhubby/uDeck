# 验证与验收

验证结论必须注明源码身份、执行环境和覆盖边界。
旧版本通过的项目不能直接作为当前版本的验收结论。
历史测试数字、部署附件和截图从 Git 历史追溯。

## 三层证据

| 层次 | 必需证据 | 证明范围 |
| --- | --- | --- |
| 源码 | 提交、dirty 状态、工具链、命令、退出码和日志 | 指定环境中的代码与自动化行为 |
| 安装包与设备 | 包哈希、构建身份、已安装文件、会话状态和功能探针 | 指定设备实际加载的实现及自动化路径 |
| 物理验收 | 设备型号、真实操作、观察结果和未通过项目 | 按键、显示、轨迹球、声音和实际体验 |

Mock 截图证明布局，不证明硬件服务。
离屏呈现不证明真实合成器帧率。
内核或 Qt 合成事件不证明实体按钮和传感器正常。
核心加载不证明游戏兼容性，CI 通过不证明设备已安装。

## 源码检查

固定工具链和日常命令见[开发指南](development.md)。
Qt 测试先设置 `QT_QPA_PLATFORM=offscreen`。
完整回归使用 `tools/test-suite`，每个测试文件独立进程执行。
这样可隔离 Qt 生命周期，保留超时、日志和 JUnit。
涉及原生终端时必须编译目标 Qt 的插件，不能用 Mock 代替。
仅修改文档时检查链接、模块清单、发行文档路径和文档引用。

## 安装包检查

使用套件中的 preflight 与 SHA256SUMS 核对目标环境及制品。
`udeckctl doctor --json` 读取冻结的构建身份。
检查已安装 Python、QML、字体和私有插件是否来自同一构建。
升级前仍运行的进程须单独标明，磁盘版本不等于已加载版本。
升级、回退、卸载重装分别验证用户配置、默认终端和登录设置。
安装操作见[发行指南](debian-distribution.md)。

## 设备功能与物理验收

- 桌面：主页、应用、Console、文件、设置的焦点和返回路径。
- 输入：ABXY、L/R、长按、中文候选、切换应用后的首次输入和释放。
- 轨迹球：正反与斜向移动、点击、长按、跨窗口连续性和滚动手感。
- 应用：文件冷暖打开、媒体定位、阅读位置、Terminal PTY 与菜单。
- 游戏：启动、暂停、恢复、原生存读档、正常退出和异常退出保护。
- 系统：Wi-Fi 多网卡、蓝牙实际播放、音量、亮度、锁屏和恢复。
- 共享：独立客户端读写、网络撤销、限时到期与目录失效。
- 会话：注销、登录、屏幕方向、崩溃恢复和原桌面回退。

主动操作前保存工作，使用隔离内容和明确的恢复步骤。
检查后读回用户配置与服务状态，列出未恢复和未验收项。
轨迹球传感器方向及实际滚动手感仍需实体复验。
本次文档整理不产生新的设备或物理验收结论。

## 证据保存

单次执行输出写入 `artifacts/<任务>/`。
保留命令、环境、构建清单、失败日志、截图及恢复结果。
CI 日志由工作流制品保存，稳定文档只记录复现方法与验收约束。
首页正式截图单独保留于 `docs/readme/`，来源见 `capture.json`。
资源许可证和上游哈希随对应源码保留。
