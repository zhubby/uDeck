# uDeck 0.2.1 多网卡热点

入口为 `Settings → Hotspot`（设置 → 热点）或 Y 快捷设置 → 热点，先选择网卡，再设置名称和密码、开启或关闭热点。每张网卡独立使用客户端或热点角色，支持一张连接上游 Wi-Fi、另一张提供热点，也支持多张网卡同时提供热点。普通 Wi-Fi 页面在网卡提供热点时显示「管理热点」入口。

## 配置与网络共享

- 初始名称为 `uDeck-接口名`，允许 1–32 UTF-8 字节；WPA2 密码允许 8–63 字节或 64 位十六进制 PSK。输入默认隐藏，X / F10 可显示本次输入，B 返回清除输入。
- 名称和密码通过 NetworkManager 保存；不会读取、回填已有密码。密码不进入公共诊断快照、状态或错误信息；只有本地 QML 编辑视图保留本次输入。
- 热点配置使用 AP、WPA2-PSK、RSN/CCMP、IPv4 `shared` 和禁用 IPv6。频段、信道、DHCP/DNS、各热点的地址段与 NAT 由 NetworkManager 管理。Linux 安装包明确依赖 `dnsmasq-base` 和 `nftables`，不启动独立的系统 dnsmasq 服务。
- 使用当前用户权限、永久 MAC 及 uDeck 配置标记识别配置，配置跟随硬件而不依赖 `wlan0` / `wlan1` 编号。不会修改外部程序的热点或已有客户端配置。
- 始终关闭 `autoconnect`。保存配置后需要手动开启；设备重启或网卡重新插入后不会自动开启热点。开启期间名称、密码只读。
- 上游选择沿用系统路由，不提供手动指定上游的界面。无上游网络时仍可提供局域网连接；热点图标只代表 AP 实际状态，不证明互联网、DNS 或转发可用。外部防火墙或端口冲突不会被程序自动覆盖。

## 启停与恢复

已有连接的网卡开启热点前确认切换及可能中断该卡 SSH。热点任务在后台按设备记录操作 ID，D-Bus 返回激活请求不等于启动成功；只有目标活动连接和 AP 模式实际激活才显示「已开启」。启动失败或 90 秒未完成时，只清理本次活动连接，再尝试恢复原客户端配置。

关闭只处理当前明确归属的热点活动连接，等待实际断开后尝试恢复原 Wi-Fi。原配置被删除、修改、被另一张网卡独占、权限拒绝或网卡已由其他连接接管时，保留实际状态并在热点菜单显示失败原因。精确恢复记录属于当前壳进程；重新启动壳后可识别并关闭已存在的 uDeck 热点，原客户端恢复交由系统自动连接或用户手动选择。

配置、确认和输入均绑定设备与 NetworkManager 实例。网卡移除或服务重启会取消所属后台任务、关闭输入弹层并清除输入；过期配置和旧请求不得操作新服务实例。全局 Wi-Fi 关闭会取消热点任务，不自动重新打开无线电。客户端扫描、连接和普通断开操作不能绕过热点管理流程。

顶部每张网卡保留自己的图标位置。客户端显示接收信号，热点显示天线广播图标；启停或恢复中显示省略点，失败显示感叹号。多个热点各自显示，实际恢复客户端后重新显示客户端信号；热点不计入上网连接数量。

## 代码审查修复

- 恢复原 Wi-Fi 时，配置校验忽略 NetworkManager 自动维护的 `connection.timestamp` 和 `802-11-wireless.seen-bssids`，避免正常断连引起的历史记录更新阻止恢复。真实配置修改和密码修改对应的 `VersionId` 仍参与校验。
- 失败操作绑定失败处理后实际观察到的活动连接。外部连接替换该连接后，清除旧错误与恢复记录；失败处理期间已被接管时也丢弃旧恢复记录。关闭失败但原热点仍在运行时，允许再次关闭并恢复原 Wi-Fi。
- 设置中的热点数量依据网卡实际 AP 模式和已激活状态计算。关闭被拒绝时仍计入正在运行的热点，同时保留失败图标与错误提示。

## 验证

自动化分别覆盖 NetworkManager D-Bus 边界的实际后端、真实控制器导航和真实 QML 渲染；Mock 和服务替身不代表无线发射或手机接入验收。QML 覆盖 1280×720 / 960×600、中英文、经典／黑暗主题和 1×／1.5×／2× 像素比，每组 15 个场景，包括输入校验、显示密码、切换确认、双热点、失败、恢复及设备移除。

2026-11-09 审查修复后最终结果：完整 pytest **1079 passed, 3 skipped**（374.20 秒），包含本次新增的 13 项回归；3 项跳过均为本地缺少原生 Terminal 插件的既有测试。Ruff 全部通过，QML 冒烟 `qmlErrors: []`。热点 QML 矩阵 8 组、共 120 次实际渲染通过；中文黑暗主题的 15 个场景已更新并导出至 `artifacts/hotspot/zh-dark/`。dbus-next 产生 13 条 Python 3.15 废弃预告，不影响本次结果。回归中发现原有 Reader 测试使用 `object.__new__` 构造 QObject 的夹具错误；已在未修改的 main 上复现，仅修正测试夹具，未改变 Reader 产品代码。
