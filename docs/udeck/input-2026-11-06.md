# 0.1.2 ABXY 与 L/R 输入修复

日期：2026-11-06，Asia/Shanghai。用户报告 uConsole 的 ABXY 与 L/R 不可用，并确认 L/R 指鼠标左/右键。

本页保留 0.1.2 的修复与实按验收记录。随后用户选择整个会话禁用鼠标；0.1.3 将 L/R 改为切页，当前交互见 [手柄模式记录](controller-mode-2026-11-06.md)。

## 实按证据与根因

本次在设备全屏检测页按顺序提示十个物理按键。用户真实按下并松开，程序等待匹配的释放事件才进入下一步，106 秒内完成；没有用设备枚举或模拟输入代替采样。

| 物理按键 | 实际事件节点 | EV_KEY code |
| --- | --- | --- |
| 上 / 下 / 左 / 右 | `ClockworkPI uConsole Keyboard`，`event6` | 103 / 108 / 105 / 106 |
| A / B / X / Y | `ClockworkPI uConsole`，`event7` | 289 / 290 / 288 / 291 |
| L / R | `ClockworkPI uConsole Mouse`，`event8` | 272 / 273 |

设备 fingerprint 为 `1eaf:0024:20230713`。方向键、ABXY 和鼠标位于三个不同的 Linux input 接口。

原版本的问题：

- 配置中 `input` 为空，虽然发现并获取了独立手柄，路由中没有按钮映射，ABXY 不触发动作。
- 八步校准只接收手柄按钮/轴事件，但实机方向键走普通键盘接口，无法越过前四步完成校准。
- 应用和设置的 L 单击仅选中，必须双击才打开；项目 MouseArea 没有接受 R 右键，无法打开上下文菜单。
- 前台恢复时没有刷新 `foreground` 诊断字段，可能与实际 `grabbed` 状态矛盾。

## 修复行为

- 对上述已确认的官方固件与匹配的按钮能力，首次运行采用明确的默认 ABXY 映射。未知固件不猜测；保存的自定义映射优先，不把其他设备的 profile 应用到当前设备。
- 允许原生 Qt 方向键推进八步校准，记录 `keyboardDirections`；ABXY 仍只接收独立手柄事件。原生字母输入不受影响。
- L 单击应用、窗口或设置即执行；R 选择指针下的项目并打开菜单。文件保留单击选择、双击打开。
- 失焦仍释放独立手柄，不独占键盘或鼠标，前台状态同步更新。手柄不作为全局返回桌面的热键。
