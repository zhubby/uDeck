# uDeck 启动加载动效

日期：2026-11-09。

## 两层启动体验

uDeck 首个可绘制画面先显示现有暖金色品牌标识、“uDeck”和“正在准备桌面…”。应用目录扫描在独立工作线程运行，Qt 窗口、控制器与输入对象保留在主线程。目录结果应用到桌面后，再经过一帧完成启动；Wi-Fi、蓝牙、音频等后台服务不构成启动门槛。扫描失败时展示错误，仍允许进入桌面和设置，不无限遮挡可用导航。初始化期间不把尚未加载的空列表当作真实列表清除已保存的应用焦点。

从首页、应用列表或应用上下文菜单打开软件时，立即建立独立等待请求；180ms 内已经出现并激活目标窗口的请求不显示浮层。较慢启动显示约 392×280 的面板、72 像素应用图标、24 像素名称和 18 像素状态文字，背景覆盖 40% 黑色，不做模糊。面板沿用当前主题和字体，保留桌面布局与原选择位置。

共享加载轨道为 160×3 像素，44 像素暖金色短线往返一次约 1100ms，没有百分比。浮层淡入 140ms、淡出 120ms；目标窗口切到前台时直接交接，不为播放动画延迟启动，也不主动把壳窗口拉回前台。

## 等待、返回与异常

| 情况 | 行为 |
| --- | --- |
| 命令调用返回 | 记录请求已发送，继续等待实际窗口；不宣称应用就绪 |
| 目标主窗口进入前台 | 完成对应请求并收起等待层；也支持已有窗口激活 |
| 按 B / Esc | 收起等待层，焦点仍在原应用；不取消进程，后台跟踪继续 |
| 重复打开同一个待启动应用 | 恢复原等待请求，不再次执行启动命令 |
| 等待超过 8 秒 | 改为“仍在等待应用窗口…” |
| 20 秒未检测到窗口 | 收起等待层并中性提示应用可能仍在启动；不自动重试、不杀进程 |
| 无窗口协议或协议中途失效 | 请求发送后最多再等待 2.5 秒，提示“已发送启动请求”，不宣称成功或失败 |
| 启动调用明确失败 | 立即收起对应等待并显示应用名称与错误原因 |
| 壳失去前台 | 收起显示，重新返回壳时不自动重弹旧浮层 |

应用匹配使用桌面条目 ID、由其得到的原生应用 ID 和 `StartupWMClass`。窗口标题不参与推断，子窗口与最小化窗口不能完成请求。每个请求独立编号，旧请求完成、失败或超时都不能清除较新的浮层；后台通知标明所属应用。

等待期间屏蔽普通导航与重复确认；B / Esc 收起等待。主页、运行中和快捷设置的已有全局动作仍可退出当前等待并执行原功能，不改变原有权限、确认或输入隔离流程。应用启动使用独立执行器，不占用文件传输或目录读取的 busy 状态。

## 主题、语言与资源

- 沿用 `ThemePalette.qml`、`InterfaceFonts.qml` 和现有应用图标；缺失图标走现有通用图标回退，不引入依赖、字体或第三方资源。
- 中英文状态由现有翻译机制提供。长应用名称截断，等待文字最多两行；1280×720 与 960×600 保持同样的文字和面板尺寸。
- `UDECK_REDUCED_MOTION=1` 时不运行流动与淡入淡出动画，使用静态金色短线和状态文字；所有隐藏浮层停止循环动画。
- 不增加启动、加载循环或完成音效。等待期间无效导航不发声，主动返回沿用已有返回音效。

## 接口与验证

控制器快照增加 `startup` 和 `appLaunch`，分别表示桌面初始化和当前可见应用等待；不改变已有应用 D-Bus 协议。`Diagnose` 新增 `startupFrameSeconds`，原有 `firstFrameSeconds` 继续代表进入桌面的首帧，而不是被更早的品牌加载帧替代。

回归入口：

```sh
PYTHONPATH=src python -m pytest tests/test_launch.py tests/test_launch_controller.py tests/test_launch_qml.py tests/test_sound_interactions.py -q
PYTHONPATH=src python tests/launch_qml_probe.py artifacts/startup-loading/classic-zh-1280 --language zh_CN --theme classic
PYTHONPATH=src python -m pytest -q
```

QML 探针实际加载桌面，通过键盘事件检查等待期间导航拦截、Esc 返回、原选择保留及后续左右导航；验证金色短线实际移动、减少动态效果下静止、隐藏后动画停止，并保存品牌启动、应用等待、长等待和返回桌面四个画面。矩阵包含两种主题、两种语言、两种分辨率与两种动态效果模式。状态测试使用可控时钟覆盖窗口早于回调、旧请求超时、重复启动及协议降级；启动测试核对目录读取不在主线程进行。

## 本轮验证记录

- 使用 Python 3.13.18、PySide6 6.8.3，显式设置当前源码的 `PYTHONPATH`。没有修复或替换原有失效的 `.venv` 解释器链接，也没有改动其他工作区的环境。
- 新增加载回归 **39 项通过**：13 项纯状态测试、9 项控制器/后台扫描测试、16 组 QML 视觉与输入矩阵、1 项主入口首帧诊断测试。新增用例与 Reader、语义音效测试在同一进程混合运行 **61 passed**。
- 所有 **76 个测试模块逐模块独立进程运行，1138 passed、3 skipped、无失败**，耗时 401.35 秒。3 项跳过均要求本机未构建的原生终端插件，不能计作真实 PTY、ANSI 或 Nerd 字形单元格验收。
- `ruff check src tests` 与 `git diff --check` 通过；保留的经典主题 1280×720、黑暗主题 960×600 中文 QML 探针均 `qmlErrors: []`，并确认返回后焦点可继续导航。
- 使用干净暂存源码构建 wheel，避免复用本地 `build/lib` 中的陈旧文件；包内 **330 个源码/资源逐字节匹配**，包含新增 Python 与 QML 组件。产物保留在 `artifacts/startup-loading/dist/`，未作为正式版本发布或安装。
- 常规单进程全量运行曾在 `test_reader_layout.py` 的 Qt 清理/事件处理阶段发生原生 Bus error，该次运行不记为通过；随后采用上述模块隔离方式覆盖完整测试集。没有为此修改 Reader 或其他无关业务代码。

完整模块 XML/日志和汇总位于 `artifacts/startup-loading/module-tests/` 与 `module-test-summary.json`。中文场景截图位于 `classic-zh-1280/`、`dark-zh-960/`；`loading-motion.gif` 由 64 张实际 QML 渲染帧合成。该动图是本地 Mock 场景预览，不代表真实启动耗时或硬件性能。

本轮仅修改源码与测试，不安装设备软件、不重启现有桌面或应用。uConsole 的 SSH 非交互认证未通过，因此真机 Wayland 交接、实体屏幕流畅度与物理 B 返回仍需单独验收；本地 QML 渲染和自动键盘事件不替代这些验收。不涉及 Linux 开机动画，也不等待网页、媒体、文档内容加载。
