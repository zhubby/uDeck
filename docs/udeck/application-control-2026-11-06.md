## 操作

| 按键 | uDeck | 第三方按键模式 | 第三方指针模式 |
| --- | --- | --- | --- |
| 方向键 | 移动焦点 | 原生方向键 | 移动指针，长按加速 |
| A | 确认 | Enter | 左键，按住拖动 |
| B | 返回 | Esc | Esc |
| X | 上下文菜单 | Shift+F10 | 右键 |
| Y | 快捷设置 | 应用控制菜单 | 应用控制菜单 |
| L / R | 上一页 / 下一页 | Shift+Tab / Tab | 向上 / 向下滚动 |

物理轨迹球与鼠标持续屏蔽。虚拟指针只在第三方应用指针模式使用，可连续短按 A 双击。实体键盘负责文字；编辑和中文输入法候选选择使用按键模式。按键模式不保证把第三方界面变成空间焦点导航。

应用控制菜单默认选择「返回应用」，可切换模式、执行常用操作、返回桌面、打开快捷设置或请求关闭。B 从子菜单逐层返回，关闭根菜单恢复原窗口；窗口已经消失则进入运行中。请求关闭使用窗口协议，保留应用自己的保存确认。

Firefox / Chromium 提供地址栏、前后页、刷新、新标签页；Mousepad / Geany / Code 提供打开、保存、查找、撤销；PCManFM 提供地址栏、上级目录、上一目录、重命名。Bookshelf、普通终端和未知应用使用通用配置。RetroArch / ES-DE 默认原生输入；uDeck Terminal 保持自身原生路由。原生模式使用 `Ctrl+Alt+Esc` 返回桌面。

## 实现与恢复

- `ApplicationRouter` 根据真实 active 窗口交接，子对话框继承父窗口应用配置。模式写入 XDG 配置的 `applicationInput`，旧字段保留。
- 原生 Wayland 虚拟键盘、虚拟指针协议兼容 Wayland / Xwayland，普通用户运行，无常驻 root 服务。IPC 只接受固定模式与菜单操作，不接受任意按键或脚本。
- 只读监听已确认的内置 Keyboard；不独占整个键盘，不把字母当 ABXY。指针模式只消费无修饰方向键，实体组合键继续投递。
- 运行时配置位于 `$XDG_RUNTIME_DIR/udeck/labwc`；每次只重载同用户、准确 `-C` 目录的 `LABWC_PID`。F24 回报随机配置代次，确认后才返回应用。虚拟键表单独补充 F24，不修改物理键盘布局。
- 超时留在菜单并请求恢复普通配置；恢复请求不等于已经取得恢复回执。旧代次与旧请求的延迟回调不会开启指针。会话监督进程在异常退出后恢复普通方向键配置。
- 窗口切换、菜单、模式切换、锁屏、会话停用、设备断开、协议失败及退出时释放注入状态并停止移动；按住的输入必须松开。方向键接口缺失时拒绝指针。窗口恢复需再次被合成器报告为 active 才发送固定快捷键。

本地命令：

```sh
udeckctl app-menu
udeckctl input-mode keyboard
udeckctl input-mode pointer
udeckctl input-mode native
udeckctl doctor --json
```

诊断 `runningShell.input.compatibility` 包含模式、应用、窗口、虚拟输入连接、方向键读取、拦截状态、配置等待与错误。窗口化预览及原桌面下明确显示不可用原因。

## 自动化验证

- 本地完整 Python / QML 回归 **185 passed、2 skipped**；两项跳过均因开发机没有构建终端原生插件。Ruff、shell 语法与 0.1.4 wheel 构建通过。
- CM4 使用已安装的原生终端插件执行完整回归，**187 passed，无跳过**，包括真实 PTY / buffer 与终端生命周期。两端均有 dbus-next 的 13 条 Python 3.15 弃用预告，不影响本次 Python 3.13 结果。
- `tools/verify-application-input.py` 仅创建自己的 Wayland / Xwayland 窗口；实际收到 Enter、Esc、Shift+F10、Shift+Tab、Tab、Ctrl+L、拖动、右键及滚轮事件，结束后释放注入状态。
- `tools/verify-input-isolation.py` 在私有 D-Bus 与自建 headless labwc 中验证真实重载回执、四方向拦截、Ctrl+Right 与字母正常投递、旧代次拒绝及普通方向键恢复。进一步接通完整路由，在两种窗口上验证按键、菜单不泄漏、指针拖动/滚动、方向键不穿透及原生模式释放。
- 私有 headless 合成器完成上述检查后在退出阶段返回 **139**；此前使用最小配置也能复现。此结果保留在 stderr 与记录中，不把私有测试结束等同于独立物理登录会话成功。

自动化创建窗口与模拟按钮不能代替物理验收，启动应用也不能证明应用内全部操作正常。

最终安装包在原 `rpd-labwc` 会话下的基线采样为 **60.059 秒**：RSS 峰值 **198.00 MiB**，末值 **197.94 MiB**，空闲 CPU **1.199%（单核口径）**，程序内部首帧 **1.525 秒**。这不是包含 Python 导入的完整启动时间，且应用兼容层处于停用状态；因此**尚未通过独立会话完整路由的性能目标**，须现场重新测量。
